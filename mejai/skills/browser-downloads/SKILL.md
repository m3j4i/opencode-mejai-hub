# Verified downloads
1. Confirm the requested format and destination. Search for real source pages; do not construct download URLs from titles.
2. Discover server navegador through habilidades, then inspect actual tool names and schemas. Navigate, read the page snapshot and extract links, including frame links when needed.
3. Use current element references for forms and buttons. Refresh the snapshot after navigation. Inspect new tabs after popups. Avoid advertisements and notification requests.
4. Download discovered file URLs using the browser session and its cookies. Button-triggered downloads are monitored too. Check download status until completion or failure; keep the browser open while downloading.
5. Verify existence, size, format and content. A SHA-256 identifies bytes; authenticity requires comparison with a trusted published hash. HTML challenge pages are not successful archives.
6. For CAPTCHA, show the page and allow ten seconds for the user to solve it. If unresolved, try a legitimate alternative source and continue independent work. Do not claim that browser changes guarantee access.
7. For simple HTTP transfers use curl.exe on Windows or curl on Linux, absolute output paths and explicit status/error checks. Discover specialized tools instead of executing MCP names in the terminal.
8. Report the saved path and checks actually performed. If blocked, state the cause and remaining work without claiming success.
